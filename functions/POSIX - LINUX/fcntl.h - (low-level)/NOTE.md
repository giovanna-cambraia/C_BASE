# <unistd.h> / <fcntl.h> — File I/O (low-level)

This is a genuinely important distinction to internalize upfront: this is a different, lower-level API than <stdio.h>'s fopen/fread/fwrite/fclose covered way back at the start. <stdio.h> functions work with a FILE* and add buffering, formatting, and portability on top. read/write/open/close work directly with raw OS file descriptors (plain integers) and do no buffering of their own — every call is a direct system call. Neither is "better" universally; <stdio.h> is what you reach for by default, and the raw POSIX calls are what you reach for when you need more direct control (custom buffering strategies, non-blocking I/O, working with things that aren't regular files — pipes, sockets, device files).

The single biggest mental shift from <stdio.h> to this raw POSIX layer: fread/fwrite mostly handle the "did I actually get all the bytes I asked for" problem internally (via their buffering layer). read/write do not — partial transfers are an explicit, expected, everyday part of the contract at this lower level, and any code treating a single read/write call as "all-or-nothing" is carrying a latent, genuinely common bug.
